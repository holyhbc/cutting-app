## 1. 目标

让车间工人用**微信扫标签二维码**报工，替代人工登记，实现：

1. 一扎多人协作，各自认领工序
2. 首次报工即时生效
3. 改量需主管审批，防止虚报
4. 自动汇总出裁剪工序完成量
5. 一键导出 Excel 交财务

### 非目标（本期不做）

- 企业微信 / webhook 消息推送
- 计件工资自动核算
- 库存扣减联动
- SQL Server 公网访问

## 4. 数据流设计

### 4.1 二维码标识（阶段 0 重点）

**问题**：二维码内容要短（微信扫一扫，密，太长扫不出/易错），但必须唯一标识一扎。

**方案**：

```
gen_short_id(zdno, cc, zh)  →  sha1(zdno|cc|zh) 前 5 字节 → base32 → 取 8 位大写
```

- 短 ID **无业务含义**，只做索引
- 碰撞概率：40bit 空间，按生日问题约 100 万条才 50% 碰撞，实际标签量远低于此；服务端再做唯一性校验兜底
- 必须带 `CC`（见 [DECISIONS.md D-002](DECISIONS.md)）

**二维码内容**（最终形态）：

```
http://<vps>/s/A7K2M9QX
```

**阶段 0 单独设计**：只生成 `short_id` + 二维码图片，**不改** `make_full_barcode()`（保持 13 位条码不变），两者独立并存。

### 4.2 报工写入（阶段 2）

```
员工登录（工号 → ygzl 校验）
    ↓
扫码 → short_id → 反查 (ZDNO, CC, ZH)
    ↓
拉取该扎全部工序 + 剩余数 = jfzd2.JS − Σjfgz.已报
    ↓
员工选择工序 + 填数量
    ↓
┌─ 首次报工 → 直接生效
└─ 改量   → 写审批表，等主管
    ↓
上限校验（同事务内，见 D-006）
    ↓
写 jfgz（barcode=1, gzdate=完整datetime）
```

### 4.3 改量审批（阶段 3）

```
员工发起改量 → jfzg_change（状态=待审）
    ↓
主管页显示角标数量
    ↓
主管通过 → 事务改 jfgz + 写审计
主管驳回 → 记录原因，通知页面
```

**绝对禁止**：直接 UPDATE 已生效的 `jfgz`。所有改动必须走审批表留痕。

### 4.4 同步（阶段 2/3 交界）

```
局域网同步器：定时 → HTTPS 拉 /api/pending → 校验 → 写 SQL Server
    ├─ 幂等：按 jfgzid / 变更单号去重
    ├─ 失败重试：指数退避
    └─ 回执：/api/ack → VPS 标记已同步
```

## 5. 数据库设计（阶段 0 不建表，先记录）

⚠️ 全部需兼容 **SQL Server 2000**：无 CTE、无 MERGE、无 `datetime2`、无 `sys.indexes`。

### 5.1 新增表：扫码映射

```sql
-- 短 ID → 工单三元组
CREATE TABLE jfzg_scan_map (
    short_id   CHAR(8)      NOT NULL PRIMARY KEY,  -- base32 大写
    zdno       VARCHAR(40)  NOT NULL,
    cc         VARCHAR(20)  NOT NULL,               -- 必填，防跨 CC 撞号
    zh         VARCHAR(40)  NOT NULL,
    created_at DATETIME     NOT NULL,
    used_count INT          NOT NULL DEFAULT 0
)
```

### 5.2 新增表：改量审批

```sql
CREATE TABLE jfzg_change (
    id          INT IDENTITY(1,1) NOT NULL PRIMARY KEY, -- 2000 无 SEQUENCE
    short_id    CHAR(8)     NOT NULL,
    jfgzid      BIGINT      NOT NULL,               -- 订正：jfgz.jfgzid 是 bigint
    gx          SMALLINT    NOT NULL,               -- 订正：工序是 ID(1~18)，不是名称
    gxname      NVARCHAR(30) NULL,                  -- 冗余存名称，方便审批页显示
    old_num     INT         NOT NULL,               -- 订正：jfgz.js 是 int
    new_num     INT         NOT NULL,
    reason      NVARCHAR(500) NULL,
    apply_gh    NVARCHAR(10) NOT NULL,               -- 申请人工号，对齐 ygzl.ygno
    approve_gh  NVARCHAR(10) NULL,                   -- 审批人工号
    status      TINYINT     NOT NULL DEFAULT 0,     -- 0待审 1通过 2驳回
    created_at  DATETIME    NOT NULL,
    approve_at  DATETIME    NULL
)
```

### 5.3 复用 `jfgz` 的写法约定

- ⚠️ **不要写 `barcode`** —— 该字段已有 125333 行为 1，语义未知（见 CURRENT_STATE 错误 2）
- ⚠️ **`gzdate` 是否写时分秒待确认** —— 历史 12.8 万条全为 `00:00:00`
- `gx` 存**工序 ID**（smallint 1~18），名称从 `jfdjgxk.gxname` 取
- `zdno` 是 `nvarchar(15)`，**实测最长 15 字符**，写入前必须校验长度
- 按 `jfgzid`（bigint）精确定位，**不做条件 UPDATE**

## 6. 标签设计

```
┌────────────────────────────────────┐
│ 268810套装  1号扎                  │
│  [13mm 二维码]  ▌▌▌▌▌▌▌▌▐▌▌▌▌  │
│                 26881011001230001 │
└────────────────────────────────────┘
   左：二维码（微信扫）
   右：原有 Code128 条码（扫码枪扫）
```

- 尺寸待阶段 0 打印样张确认，放不下则缩放或加长标签纸（D-010）
- **不改条码格式**，避免 13→14 位兼容风险（D-011）
