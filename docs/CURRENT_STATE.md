## 三、⚠️ 实库核查推翻了 5 个假设（2026-10-09）

只读核查 `ShintHrmDb` 后，以下文档原假设**被证伪**：

### ❌ 错误 1：`jfzd2` 没有工序字段 —— 最严重

`jfzd2` 真实字段只有 8 个：

| 字段 | 类型 | 含义 |
|---|---|---|
| `ZDNO` | nvarchar(15) | 定单号 |
| `CC` | smallint | 车间/层 |
| `ZH` | int | 扎号 |
| `GH` | nvarchar(10) | 工号（**大部分为空**） |
| `YS` | nvarchar(10) | **颜色**（黑色/深麻灰/宝兰…） |
| `CM` | nvarchar(8) | **尺码**（均码/XL/S-M/L-XL…） |
| `JS` | smallint | 数量 |
| `MDATE` | smalldatetime | 日期 |

**结论：`jfzd2` 是「一扎 × 颜色 × 尺码」，不是「一扎 × 工序」。**
一个 `(ZDNO,CC,ZH)` 通常只有 **1 行**（抽样的 3 扎全是 1 行，均码）。

→ **设计必须改**：不能按 `jfzd2.JS` 做「该工序应做数」的上限校验。
→ **待确认**：一扎对应哪些工序？工序从哪张表取？（见第六节）

### ❌ 错误 2：`barcode` 不是"扫码/人工"标记

实库分布：

| barcode | 行数 |
|---|---|
| 1 | **125333** |
| 0 | 2815 |

且两个值在同一个月内交替出现（如 2026-08-10：1 有 3446 行，0 有 189 行）。

→ **原 D-003 决策作废**，`barcode` 已被历史数据占用，语义未查明（疑似"已审核/已记账"）。
→ **绝对不能**直接拿来当扫码标记，否则会污染 12.5 万条历史统计口径。

### ❌ 错误 3：`gzdate` 历史上全是 `00:00:00`

抽样全部为 `2026-09-07 00:00:00` 形式，**12.8 万条都是纯日期、零时分秒**。

→ **原 D-004 决策有风险**：新数据写完整 datetime 会与历史不一致，可能影响现有工资/报表的按日聚合。
→ **待确认**：是否坚持写完整时间，还是跟随历史只写日期。

### ❌ 错误 4：工序编号有三套，互相冲突

| 来源 | 编码形式 | 规模 | 问题 |
|---|---|---|---|
| `jfgz.gx` | smallint `1`~`18` | 17 个实际值 | 看起来可信 |
| `jfdjgxk.gxid` | char(2) `'01'`~`'48'` | 48 行 | 工序库，含单价 |
| `jfdj.gx` | smallint `1`~`657` | — | ⚠️ **不可信**：gx≥19 的 `gxname` 全为空，且 gx≥19 之后每值固定 3 行，像是自增行号而非工序号 |

→ **不能信任 `jfdj.gx`**。工序主数据应以 `jfdjgxk`（48 条，带名称和单价）为准。

### ❌ 错误 5：`jfgz.js` 与 `jfzd2.JS` 量级不符

```
jfzd2.JS 合计 =  9,971,939
jfgz.js  合计 = 48,078,613     ← 约 4.8 倍
```

→ 说明 `jfgz.js` 是**跨工序累计的报工量**，不受 `jfzd2.JS` 总量约束。
→ 原 D-006「合计不得超过 `jfzd2.JS`」的上限基准**取错了字段**。

### ✅ 核查确认成立的

- **D-002 正确**：跨 CC 重复的 `(ZDNO, ZH)` 恰好 **59 组**，与文档一致。
  例：`10039包缝616-661` 的 zh=648/639/616/657/634 均有 2 个 CC。
- `jfgz.jfgzid` 是 **bigint IDENTITY**（原文档写成 int，需订正）。
- `ygzl` 116 人，含 `ygno` / `ygname` / `ygout`（离职标志）。A001 陈秋雪、A003 罗细娇，与主管名单猜测一致。

## 六、阻塞设计的待确认问题

按优先级：

1. **`barcode` 字段真实语义是什么？** —— 决定扫码数据能否复用 `jfgz`（最高优先）
2. **一扎到底对应哪些工序？** —— `jfzd2` 无工序字段，需指明工序来源表
3. **`gzdate` 写完整时间还是只写日期？** —— 影响与历史数据的一致性
4. **数量上限拿什么字段做基准？** —— `jfzd2.JS` 总量和 `jfgz.js` 差 4.8 倍
5. 工序编号以 `jfdjgxk`（48 条）为准可以吗？
6. 扫码枪是否支持 14 位 Code128？（不阻塞，二维码走独立短 ID）
7. 标签纸实际尺寸，13mm 二维码能否与条码并排？

## 七、硬性约束

1. **禁止对 `ShintHrmDb` 做写入测试**，一律用 `ShintHrmDb-test`
2. SQL Server 2000：禁止 CTE / MERGE / `sys.indexes` / `syscolumns.is_identity` / `datetime2`
   - IDENTITY 检测用 `COLUMNPROPERTY(OBJECT_ID(t), col, 'IsIdentity')`
3. **改条码前先 commit**
4. 扫码标签必须带 `CC`（59 组重复已证实）
5. **不要在查明语义前使用 `jfgz.barcode`**
6. **不要信任 `jfdj.gx`**
