## 二、为什么不用「手机号 + 密码」（实库核查结论）

原设想是「手机 + 密码登录页」。核查 `ygzl` 后**这条路走不通**：

| 字段 | 有值/116 | 结论 |
|---|---|---|
| `con_tel` 联系电话 | **1** | ❌ 几乎没录 |
| `ygsend1`~`ygsend6` | **0**（且是 decimal，是金额不是号码） | ❌ |
| `id_no` 身份证 | **0** | ❌ |
| `cardid` 卡号 | **0** | ❌ |
| `ygno` 工号 | 116/116，唯一 | ✅ 可作主标识 |
| `ygname` 姓名 | **有 2 组重名**（林和女×2、杨尚听×2） | ⚠️ 不能单独标识 |

> 若要用手机号登录，得先录约 30 人的手机号（见第六节导入脚本）。
> 实测只有 1 人有，故不能把手机号当作**已有**的登录凭证。

**结论**：登录标识做成 **工号 或 手机号 二选一**，两者都接受。
工号记不住的人填手机号，两者都记得的人随便填哪个。

**重名处理**：登录和报工**一律用工号**，姓名只作显示。
页面显示成 `张诚（A005）`，重名时也能分辨。

## 三、R1 员工记忆机制

### 流程

```
首次
  扫码 → 登录页
       → 填「工号 或 手机号」+ 4位 PIN
       → 服务端：用工号或手机号查出 ygno
                → 查 ygzl（在职？active=1？）
                → 校验 PIN 哈希
       → 签发令牌（**无到期日**）
       → 存 worker_login.session 记录
       → 令牌存本机 localStorage

之后
  扫码 → 页面读 localStorage 令牌
       → 每次都重新查 ygzl 确认在职
       → 显示「👤 张诚 A005 [切换]」，跳过登录
```

### 表结构

```sql
-- 登录凭据：工号/PIN/手机号/是否激活
CREATE TABLE IF NOT EXISTS worker_login (
    ygno        TEXT    PRIMARY KEY,          -- 工号，主标识
    ygname      TEXT    NOT NULL,             -- 姓名，仅显示
    phone       TEXT,                         -- 手机号，可空
    pin_hash    TEXT    NOT NULL,             -- PIN 哈希，不存明文
    pin_salt    TEXT    NOT NULL,
    must_change INTEGER NOT NULL DEFAULT 1,   -- 首次登录提示改 PIN
    active      INTEGER NOT NULL DEFAULT 1,   -- 0 = 不能登录
    created_at  TEXT    NOT NULL,
    updated_at  TEXT
);
-- phone 可为 NULL，SQLite 的 UNIQUE 允许多个 NULL，不影响没手机号的人
CREATE UNIQUE INDEX IF NOT EXISTS ux_worker_login_phone ON worker_login(phone);

-- 登录态令牌：长期有效，靠每次查 ygzl 兜底
CREATE TABLE IF NOT EXISTS worker_session (
    token      TEXT    PRIMARY KEY,
    ygno       TEXT    NOT NULL,
    created_at TEXT    NOT NULL,
    expires_at TEXT    NOT NULL,      -- 远期（按用户要求长期有效）
    last_seen  TEXT    NOT NULL,
    device     TEXT    NOT NULL DEFAULT ''
);
CREATE INDEX IF NOT EXISTS ix_session_ygno ON worker_session (ygno);

-- R2 工序偏好：覆盖式，只留最新一道
CREATE TABLE IF NOT EXISTS worker_pref (
    ygno       TEXT    NOT NULL,
    scope      TEXT    NOT NULL,      -- 'bundle' 或 'zdno'
    zdno       TEXT    NOT NULL,
    cc         INTEGER NOT NULL,
    zh         INTEGER NOT NULL,
    gx         INTEGER NOT NULL,
    updated_at TEXT    NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS ux_pref_bundle
    ON worker_pref (ygno, scope, zdno, cc, zh);
```

### 手机号归一化

存之前只保留数字，剥掉 `+86`：

```python
def norm_phone(s):
    d = re.sub(r'\D', '', str(s or ''))
    if d.startswith('86') and len(d) == 13:
        d = d[2:]
    return d or None
```

`"138 1234-5678"`、`"+8613812345678"` 都要归一化成 `13812345678`，
否则工人怎么打都对不上。

## 四、初始 PIN = 手机号后 4 位

**已确认方案 A。**

```python
pin = phone[-4:]        # 13812345678 -> 5678
```

**理由**：工人只需记住**一样东西** —— 自己的手机号。
后 4 位不用另外记，也不用班组长发卡片。

### 强度说明（如实告知）

知道完整手机号的人可以登入（工友瞥一眼号码即可），
所以强度约等于「要同时知道手机号」。
相比「只知道工号」是提升的，但不是密码级。

**兜底**：
- 首次报工直接生效，但**改量必须主管审批**（[D-005](DECISIONS.md)），
  冒名的最坏后果是「多报一次首次数量」，金额有限且事后可查 `jfgz` 的 `ygno`
- 页面**常驻显示姓名与工号**，共用工友一看就知道是谁
- 提供显眼的「切换」按钮

`must_change=1` 会提示工人登录后改成自己好记的 4 位。

## 五、只激活约 30 人

116 人里约 30 人在裁剪车间，其余 `active=0` —— **根本登不进去**。

好处：
- 手机号只需录 30 个
- 避免离职/调岗的人误登
- 登录失败原因更清晰

**两个开关的分工**：

| 字段 | 谁来改 | 含义 |
|---|---|---|
| `ygzl.ygout` | 人事 | 离职，**永久**失效 |
| `worker_login.active` | 班组长 | 暂时不用（调去别的车间），可随时开 |

### "直到离职"如何保证

**每次使用都查 `ygzl`**，不靠人工删令牌：

```python
emp = 查 ygzl(ygno)              # 1. 人还在吗？
if emp is None or emp.ygout == 1: 令牌立即作废   # 2. 离职即失效
verify(emp.ygno, pin)            # 3. 校验 PIN
```

`ygzl` 一改，第二天就登不进去。这比管理员手动禁用可靠得多。

## 七、R2 工序记忆

### 记忆粒度：两级回退

```
① 查 (工号, 定单, 层, 扎)  → 精确记忆：这扎上次做的哪道
② 查不到则查 (工号, 定单)  → 款式记忆：这一单他一直在做同一道
③ 都没有 → 不预选，让他自己点
```

**为什么两级**：
- 流水作业里一个工人往往连续几扎做同一道 → ②命中率高
- 同一扎内偶尔换人接手 → ①兜底，避免记错

偏好是**覆盖式**的，不记历史，只留最新一道。

### 数量预填规则

预填**该工序的剩余应做数**，不是"上次报了多少"。

原因：工人这次要补的是**没做完的部分**，预填上次数会反复报同样的数。

```python
remain = plan_qty - reported_qty(该扎该工序)
input.value = remain if remain > 0 else ""
```

### 边界情况

| 情况 | 处理 |
|---|---|
| 记忆的那道工序**已做满** | 不预选，提示「上次做的『衣线头』已做完，换一道?」 |
| 这扎只有一道工序 | 直接预选，无需操作 |
| 工人**换了工序** | 手动点其他工序，同时**覆盖记忆** |
| 工序很多（>10） | 记忆的项**自动滚动到可见位置** |

## 十二、风险

| 风险 | 缓解 |
|---|---|
| 令牌泄露即可冒名 | 页面常驻显示姓名工号 + 改量需审批兜底 |
| PIN=手机后4位，知道号码即可登入 | 提示工人改成自选 4 位（`must_change`） |
| 记忆错了导致连报同一道 | 预填剩余数，做满后自动不预选；各工序剩余一眼可见 |
| 多工人共用一台手机 | 「切换」按钮显眼，切换后立即生效 |
| 手机号录错/重复 | 导入脚本校验 + 唯一索引 + 汇总报告 |
| localStorage 被清 | 静默回退到登录页，功能不受影响 |
