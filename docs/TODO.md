## 🆕 用户提出的后续需求（2026-10-09）

### R1 员工身份记忆 —— 第二次扫码不用重填工号
**现状**：每次扫码都要手填工号。
**目标**：首次填工号后记住，之后自动带出；连续报工时完全不用再输入。
**可能做法**：
- 服务端签发长期令牌，存在手机本地（localStorage / Cookie）
- 令牌绑定工号，凭 `ygzl` 校验有效性（离职即失效）
- ⚠️ 需权衡：便利 vs 冒名风险。**建议**：同一工号当班次内免填，次日失效；改量仍要主管审批兜底
**待确认**：免填有效期多久？是否需要"切换员工"入口（共用手机时）

### R2 工序记忆 —— 同一扎重复扫不必重新勾选
**现状**：每次都要点工序。
**目标**：记住"这个工人上次在这扎做的是哪道工序"，下次扫码自动选中并预填剩余数。
**可能做法**：
- 服务端记录 `(工号, zdno, cc, zh) -> 上次工序`
- 扫码页默认选中上次工序，数量预填「剩余应做数」
- 工人要改选其他工序时点一下即可
**待确认**：是否按"工号+扎"记忆，还是按"工号+定单"记忆（后者更符合流水作业）

### R3 数据查询
**现状**：只能看待同步列表 `/admin/pending`。
**目标**：工人/主管能查报工记录。
**建议分层**：
- 工人：查自己的报工记录（按日期/扎号）
- 主管：按扎/工序/日期汇总
- ⚠️ 必须加鉴权。扫码页现在**任何人扫标签都能报工**，查询更敏感
**待确认**：查询用谁的权限看？主管名单仍是 `SUPERVISORS` 环境变量？
